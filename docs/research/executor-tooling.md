# Executor and tooling facts (research agent, 2026-11-01)

## Q1a. Remote Control: what it is and what it lets a remote device do on the local PC
CONFIRMED (official doc). Remote Control connects claude.ai/code or the Claude iOS/Android app to a Claude Code session RUNNING ON YOUR MACHINE. Direction: remote device -> local session (the web/mobile UI is 'a window into that local session'). What stays available: your local filesystem, local MCP servers, tools, project config; '@' autocompletes local file paths; permission prompts and AskUserQuestion are forwarded to the device and kept open until answered; attachments from phone/browser are downloaded to your machine and passed as @ file refs; push notifications to phone when a task finishes or needs a decision. Constraints: computer must stay on and the `claude` process must keep running; one remote session per interactive process (server mode `claude remote-control` serves many, with --spawn worktree|same-dir|session); local-only commands (/plugin, /resume) don't work from the device; /model, /effort etc. take args. Requirements: Pro/Max/Ultra/Team/Enterprise subscription, claude.ai login (API keys NOT supported), no Bedrock/Vertex/Foundry, no ANTHROPIC_BASE_URL gateway, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC / DISABLE_GROWTHBOOK must be unset; ZDR and HIPAA orgs can't enable it. Start via `claude remote-control` (server), `claude --remote-control` (interactive), or `/remote-control` in a running session (CLI, Desktop app, VS Code). Remote Control vs cloud sessions: Remote Control executes on your machine; cloud sessions execute on Anthropic-managed infra.
Source: https://code.claude.com/docs/en/remote-control.md

## Q1b. Remote Control on Windows
PARTIALLY CONFIRMED. The official Remote Control doc's Requirements section lists NO operating-system restriction (only plan/auth/network/feature-flag requirements) — I could not find an explicit 'supported on Windows' sentence, so treat the official OS support statement as UNCONFIRMED. Evidence it works on native Windows: (a) anthropics/claude-code issue #48949 contains user logs from Windows 11 (Claude Desktop MSIX 1.24012.9.0, bundled Claude Code 2.1.219; also standalone CLI 2.1.220 and 2.1.209) showing `[remote-control] bridge_state: connected` / `Remote control enabled: https://claude.ai/code/...` and sessions visible as Connected in the mobile app; the issue itself is about Remote Control NOT auto-re-enabling after Desktop restart/reboot (all sessions come back with RC off; manual /remote-control or /rc re-enable works; maintainers marked #68250 duplicate on 2026-08-25). (b) The Desktop app doc describes Remote Control switch and 'Connect new sessions to Remote Control' setting in Settings > Code, and documents Windows-specific modes (native, WSL 2). (c) The cross-session messaging doc states that feature works 'on native Windows' from v2.1.234 and that a session connected to Remote Control can reach your Remote Control sessions on other machines and your cloud sessions. (d) Claude Code itself supports native Windows (PowerShell/CMD installers; Git for Windows recommended for Bash tool, else PowerShell tool; sandboxing NOT supported on native Windows, supported in WSL 2). Practical caveat from the issue thread: Remote Control is tied to the `claude` process PID, so app restarts/reboots drop it; workaround is a long-lived `claude --remote-control` / `claude remote-control` in a persistent terminal.
Source: https://github.com/anthropics/claude-code/issues/48949

## Q1c. Can a CLOUD session reach the local PC? (the inverse direction)
CONFIRMED (docs) + one UNCONFIRMED environment observation. Official path: cross-session messaging — a cloud session can message your Remote Control sessions on other machines (messages travel through Anthropic servers over that machine's Remote Control connection), and your local session connected to Remote Control can message cloud sessions. Requires Claude Code v2.1.224+ (macOS/Linux/WSL2) or v2.1.234+ (native Windows). A WSL2 session and a native Windows session on the same PC cannot reach each other. Separately, this cloud session's own tool `list_computer_folders`/`request_computer_folder` (Claude Code Remote tools) describes attaching a cloud session to a folder served by the user's computer via Remote Control, and its description states the folder must be 'on a Mac or Linux computer' — i.e. the cloud-attaches-to-local-folder path currently excludes Windows. UNCONFIRMED: no public URL for that tool description; it is the tool text visible in this session only. Also relevant: Dispatch (message a task from mobile; runs on your machine via Desktop app) and `claude --teleport` (pull a cloud session into your terminal).
Source: https://code.claude.com/docs/en/cross-session-messaging

## Q1d. Windows setup matrix for Claude Code (native vs WSL)
CONFIRMED. Official setup doc table: Native Windows — requires nothing (Git for Windows optional), sandboxing NOT supported, for Windows-native projects/tools. WSL 2 — sandboxing supported, for Linux toolchains. WSL 1 — not supported for sandboxing. Install: PowerShell `irm https://claude.ai/install.ps1 | iex`; CMD `curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd`. Desktop app on Windows can run sessions inside a WSL 2 distribution (code.claude.com/docs/en/desktop-wsl); WSL sessions may lack the integrated terminal/connectors. Changelog notes Windows ARM64 native binary support and 'Added support for native Windows (requires Git for Windows)' in 1.0.5x era; many Windows PowerShell-tool fixes through 2.1.2xx.
Source: https://docs.anthropic.com/en/docs/claude-code/setup?type=company

## Q2a. Current Claude Agent SDK: packages, install, auth
CONFIRMED. Packages: TypeScript `npm install @anthropic-ai/claude-agent-sdk` (Node 18.14+); Python `pip install claude-agent-sdk` / `uv add claude-agent-sdk` (Python 3.10+). Both bundle a native Claude Code binary (exceptions: ARM64 Windows pip sdist, or `npm ci --omit=optional`). Auth: ANTHROPIC_API_KEY (Console) or Bedrock/Vertex/Foundry env flags; SDK does NOT load .env. Note in docs: 'Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK' — i.e. a custom harness must run on API-key billing, not a Max subscription. SDK positioning table: Agent SDK = embed Claude Code's agent in your own process; Claude Code CLI = interactive terminal; Client SDK = raw API; Managed Agents = Anthropic-hosted harness with cloud or self-hosted sandbox (platform.claude.com/docs/en/managed-agents/overview).
Source: https://code.claude.com/docs/en/agent-sdk/quickstart.md

## Q2b. Agent SDK: subagents
CONFIRMED. Subagents are supported in both SDKs. Programmatic definition (recommended) via the `agents` option (dict of AgentDefinition: description, prompt, tools, disallowedTools, model, effort, maxTurns, background, initialPrompt) — Claude invokes them through the Agent tool; filesystem definition via `.claude/agents/*.md` also works. Features: run in parallel, isolate context, foreground/background (`background: true` non-blocking), per-subagent model/effort override, nested subagents, resume a subagent by resuming the parent session and referencing the agentId (TypeScript messages carry `agent_id`), `max_budget_usd` cap covers subagent spend (Claude Code v2.1.217+). Subagent transcripts are stored separately and survive main-conversation compaction.
Source: https://code.claude.com/docs/en/agent-sdk/subagents

## Q2c. Agent SDK: hooks
CONFIRMED. In-process callback hooks in both SDKs. Events available in BOTH Python and TypeScript: PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SubagentStart, SubagentStop, PreCompact, PermissionRequest, Notification. TypeScript-only: PostToolBatch, UserPromptExpansion, MessageDisplay, StopFailure, PostCompact, PreModelSwitch, PostModelSwitch, PermissionDenied, SessionStart, SessionEnd, Setup, TeammateIdle, TaskCreated, TaskCompleted, Elicitation, ElicitationResult, ConfigChange, InstructionsLoaded, WorktreeCreate, WorktreeRemove, CwdChanged, FileChanged, DirectoryAdded. Python can still use SessionStart/SessionEnd as shell-command hooks in settings.json. Hooks can block/modify tool calls, inject context, return systemMessage/continue; matchers are regex on tool names (e.g. `^mcp__`); default timeouts 600s (30s for UserPromptSubmit/model-switch, 10s MessageDisplay); multiple hooks run in parallel, most restrictive permission wins. Caveat: hooks may not fire when max_turns is hit.
Source: https://code.claude.com/docs/en/agent-sdk/hooks.md

## Q2d. Agent SDK: long sessions, resume, budgets (harness-building relevance)
CONFIRMED. Options (Python ClaudeAgentOptions / TS Options): `max_turns`, `max_budget_usd` (no limit by default; result subtypes error_max_turns / error_max_budget_usd; resume with higher limit), `continue_conversation`, `resume` (session ID), `fork_session`, `resume_session_at`/`resume_drops_turn` (branch from earlier point), `session_store` adapter to mirror transcripts to your own backend so another host can resume (for CI/ephemeral containers), `setting_sources` to load CLAUDE.md/skills/hooks, `effort`, `thinking`, `fallback_model`, `task_budget` (API-side token budget beta). Automatic compaction when context nears the limit (emits compact_boundary system message). Python `ClaudeSDKClient` keeps one session across many `query()` calls and supports `interrupt()`; `query()` is single-shot. Sessions created via SDK/`claude -p` are hidden from the CLI picker but resumable with `claude --resume <id>`. Hosting guidance page exists for Docker/cloud/CI (code.claude.com/docs/en/agent-sdk/hosting.md). Also from Claude Code sessions doc: Sonnet 5 default auto-compact window is its full 1M context (changelog).
Source: https://code.claude.com/docs/en/agent-sdk/agent-loop.md
